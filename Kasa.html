Contexte

Une application React
de location entre particuliers

Kasa est une application web de location d'appartements entre particuliers, développée intégralement en React à partir de maquettes Figma responsive.

Ma mission a été de développer l'ensemble de l'application : les composants React, les routes React Router, la logique de récupération des données et la suite de tests unitaires, en suivant fidèlement les maquettes fournies.

Architecture

  • 7 composants React réutilisables
  • React 18 avec Vite comme bundler
  • React Router pour la navigation
  • Hooks personnalisés pour la gestion des données
  • Suite de tests unitaires avec Vitest

Structure du projet

Organisation modulaire : components/ pour les composants réutilisables, pages/ pour les pages principales, hooks/ pour la logique métier partagée, et un dossier tests/ à côté de chaque composant.

Pages de l'application

Le parcours utilisateur

Accueil

Catalogue de logements

Bannière avec image et slogan, puis une grille de cards (3 colonnes en desktop, 1 en mobile). Les données sont récupérées via le hook useFetch, qui gère le chargement, les erreurs (redirection vers 404) et l'affichage.

Logement

Détail d'une propriété - /logement/:id

Structurée en 3 sections : carrousel d'images (Gallery) en haut, informations du logement et de l'hôte avec tags et note en étoiles (Rating) au milieu, puis deux collapses côte à côte (description et équipements) en bas.

À Propos

Valeurs de l'entreprise

Bannière avec image de paysage, suivie de 4 collapses (Fiabilité, Respect, Service, Sécurité) réutilisant le même composant Collapse que la page Logement — démonstration concrète de la réutilisabilité des composants React.

Page 404

Gestion des erreurs de navigation

S'affiche dans 3 cas : URL invalide tapée par l'utilisateur, erreur API sur la page Home, ou ID de logement inexistant. Une route catch-all (*) dans React Router redirige toutes les URLs non définies vers cette page, avec un lien de retour vers l'accueil.

Hooks personnalisés

Centraliser la logique métier

J'ai créé un hook personnalisé useFetch pour centraliser la logique de récupération des données depuis l'API. Ce hook gère trois états : data pour les données récupérées, loading pour indiquer le chargement, et error en cas de problème. J'utilise useEffect pour lancer la requête au montage du composant, et je mets à jour les états en fonction du résultat.

Cette approche évite de dupliquer la logique de récupération des données dans plusieurs composants. En centralisant cette logique dans un hook réutilisable, le code devient plus lisible, plus maintenable et plus facile à faire évoluer — les composants se concentrent uniquement sur l'affichage.

La gestion des erreurs s'appuie sur ce même principe : trois cas distincts (URL invalide, erreur API, ID de logement inexistant) redirigent tous vers la page 404 via le composant Navigate de React Router, assurant une expérience utilisateur cohérente.
